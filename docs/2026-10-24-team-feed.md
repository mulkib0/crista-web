## 행적은 어디서 오나

기능 모듈을 하나하나 고치지 않는다.

1. **모둠 채널 소식** — `Hub.onTeamMessage` 로 모둠 채널에 나가는 'board.changed'(이유 · 한 사람) · 'screen.changed' · 'doc.reviewed' · 'learn.graded' 를 받아
   `describeTeamMessage`(features/feed.ts `REASONS` 표)가 문장으로 바꾼다. 커밋 뒤 따로 쓰고, 실패하면 로그만 남긴다(원래 기록은 각 기능 표에 있다).
   모르는 이유는 남기지 않는다 — **새 기능은 `REASONS` 에 한 줄을 더한다.** 진행률 · 학습 갱신 · 시스템 '다시 읽기' 소식은 남기지 않는다.
2. **전광판 소식** — `onBoardEvent('team-feed')` 가 그 모둠 소식의 규칙 문구를 같은 트랜잭션(세이브포인트)에서 시스템 행적으로 넣는다.

같은 사람이 같은 행적을 10분 안에 잇달아 하고 그 줄이 모둠의 마지막 줄이면 새 줄 대신 `repeat` 를 늘린다(노트 고치기 등).

## 저장 · 읽음 (0019)

- `team_feed` 한 표에 대화 · 행적. 순번 `team_seq` 는 `team_feed_heads` 행 잠금 안에서 +1 → 순번 순서 = 커밋 순서. 이 잠금은 잠금 순서의 맨 끝.
- 읽은 위치는 (사람, 채널)마다 하나, 앞으로만(`greatest`). 안 읽음 = 남이 썼고 · 지우지 않았고 · `team_seq > max(그 단계 채널 위치, 'all' 위치)`(web-contract `isFeedUnread`).
  '모둠 전체'를 읽으면 모든 채널이 읽힌다. 보기는 읽은 위치를 옮기지 않는다. 읽음은 탭이 보이고 · 창이 앞에 있고 · 맨 아래일 때 0.6초 모아 보낸다.
- 지운 대화는 본문을 DB 에 남기고 화면에 보내지 않는다(교사 확인용 — 교사 화면은 아직 없다).

## API · WS

| | |
| --- | --- |
| `GET /api/feed?view=&before=&limit=` | 보기의 줄(오래된 것 → 새 것) · 채널 요약 · 나를 부른 글 수 · 내 읽은 위치 · 모둠원(접속) |
| `POST /api/feed/messages` `{ body, stepId, clientId }` | 201 새 줄 · 같은 clientId 는 200 같은 줄 · 사람마다 1분 20개(429) |
| `DELETE /api/feed/messages/:id` | 내 대화만(남의 것 403) |
| `PUT /api/feed/read` `{ channel, seq }` | 읽은 위치(앞으로만) → 새 요약 |
| WS `feed.posted` · `feed.updated` | 모둠 채널에 줄을 그대로 싣는다(모둠원만 받는 채널 · 대화는 지연 없이). 다시 붙으면 GET 으로 맞춘다 |
| WS `feed.presence` · `feed.typing` | 연결이 생기거나 끊길 때 접속 목록 · 입력 중(저장 없음 · 연결마다 3초에 한 번, 본인 연결 제외) |
