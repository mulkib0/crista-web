>
> **사용자 결정 요약 (2026-10-23)**
> 1. **화폐 단위 및 초기 연구비**: 가상 화폐 **`크리스타(CRISTA)`** 사용, 모둠 초기 연구비 **`10,000,000 크리스타`(1,000만 크리스타)**에서 시작.
> 2. **모든 수업 형태(100분 단기 · 50분×2~3차시 분산 · 상시 오픈 자율형) 대응**: 달력 날짜(자정)나 게임 시계 대신 **「파이프라인 단계(Step) 기준 가동률 + 현실 10분 주기 실시간 충전(단계별 상한 + 전원 가동 시 잔여분 즉시 정산)」** 방식 채택.
> 3. **연구 노트 보상 분리 + 심화 서술형 문항 + 진행 제한 없음**:
>    - **문항 3단**: **개념**(객관식·숫자) · **중급**(모둠 데이터 바인딩 짧은 서술) · **심화**(단계별 신약 개발 원리·시나리오 심층 서술형 문제).
>    - **연구 노트**: 단계마다 연구 노트 3칸을 꾸준히 작성해 평가받는 것을 **별도의 연구비 지급 통로**로 포함(3칸 분담 작성 시 `×1.2` 보너스).
>    - **진행 제한 없음**: 문항이나 연구 노트 채점을 받지 않아도 다음 단계 진행은 절대 막지 않는다(연구비만 빠듯해질 뿐).
> 4. **Series A / B 투자 자동 심사 (교사 승인 폐지)**: 교사 승인 없이, **모둠원 4명이 각자 발굴·실험한 신약 후보 물질들의 실제 데이터**(표적 근거 탐색 · 스크리닝 컷오프 · 4인 병렬 도킹 ΔG/PLIP · 주력 리드 및 백업 후보의 ADMET 균형 · 특허 · IND 설계) + 연구 노트/피치를 **정량 규칙(70%) + LLM 루브릭(30%)으로 종합 평가**해 즉시 차등 지급한다.
> 5. **LLM 호출 위치**: `crista-web` 서버(`apps/server`)에서 직접 OpenRouter 를 호출한다(`crista` 워커 무변경).
> 6. **유지비 대체**: 시간 경과에 따른 유지비(음수 차감)를 완전히 없애고 **기초 연구비(양수 충전)**로 대체한다.
> 7. **밸런스 문서 분리**: 세부 금액 · 배율 · 시나리오별 수지 분석은 [`2026-10-23-learning-grant-balance.md`](2026-10-23-learning-grant-balance.md) 에서 관리한다.

## 1. 원칙 — 학습이 먼저, 진행은 자유롭게

1. **문항은 모둠의 실제 데이터에 붙는다.** "TPSA 가 무엇인가"가 아니라 "우리 리드의 TPSA 112 가 AChE(중추신경) 표적에 왜 문제인가". 작업 흐름 밖의 퀴즈가 아니라 작업의 일부다.
2. **어떠한 강제 잠금도 두지 않는다.** 문제를 안 풀어도, 연구 노트 채점을 안 받아도 연구비만 있으면 다음 단계로 넘어갈 수 있다. 반대로 연구비가 부족해지면 스스로 필요를 느껴 문항을 풀고 연구 노트를 다듬게 된다.
3. **피드백 → 수정 → 재채점.** 틀린 데서 배운다. 채점 피드백을 보고 수정본을 내면 **오른 점수 차액만큼만 추가 지급**한다(대충 내고 고치는 전략이 이득이 아니게 문항·노트당 수정은 1회).
4. **간격을 두고 다시 묻는다.** 70점 미만 문항은 다음 단계 진입 후 변형 문항으로 복습 큐에 돌아온다(복습 보상은 반값).
5. **함께, 그러나 벌이 아니라 가속.** 모둠원 전원이 각자 맡은 후보 실험과 학습에 참여하면 기초 연구비가 빨라지고 Series 투자 평가 점수가 올라간다. 안 한 모둠을 전광판에 올리지 않는다(학습 소식은 긍정 소식만).
6. **정답을 돈으로 사지 못한다.** 힌트는 무료 1회(루브릭 핵심 키워드만). 힌트를 쓰면 그 문항 보상 상한 70%.
7. **채점은 투명하다.** 채점 뒤 루브릭 · 항목별 결과(○ · △ · ×) · 피드백을 보여 주고, 이의 제기 → 교사 정정. 같은 학급은 같은 모델 · 같은 프롬프트 판(`graderVersion`).
8. **개인 지갑은 없다.** 번 크리스타는 모두 모둠 연구비로 들어간다. 개인의 기여는 비교표 `byName` · 연구원 직급(인턴~수석) · 배지로 드러난다.

## 2. 연구비가 들어오는 네 통로

> 상세 금액과 예산 시뮬레이션은 [`2026-10-23-learning-grant-balance.md`](2026-10-23-learning-grant-balance.md) 참조.

### 2.1 통로 ① — 3단 문항 보상 (개념 · 중급 · 심화)

파이프라인 하위 단계(`1.1` ~ `4.2`, 8단계)마다 **개념 · 중급 · 심화** 3단 문항이 열린다.

| 단 | 형식 | 채점 방식 | 문항당 최대 보상 | 단계당 학생 제공량 | 특징 |
| --- | --- | --- | --- | --- | --- |
| **개념** | 객관식 · 복수 선택 · 숫자 | 서버 규칙(순수 함수 즉시 채점) | `25,000 크리스타` | 2문항 | `crista` CRO 문제 은행(`game-rules/gamification/cro.ts`) 사본 + 규제/임상 문항 — 시드 결정적 · 학생마다 숫자 변형 |
| **중급** | 짧은 서술형 (40~400자) | LLM 루브릭 (3~4항목) | `75,000 크리스타` | 1문항 (+수정 1회) | **모둠 실제 데이터 바인딩**(§3.2) — 우리 모둠의 표적 · 컷오프 · 도킹 ΔG · ADMET 수치 해석 |
| **심화** | 심층 서술형 (100~800자) | LLM 루브릭 (4~5항목) | `150,000 크리스타` | 1문항 (+수정 1회) | **신약 개발 원리 · 딜레마 추론 문제** — 단계별 핵심 의사결정 딜레마(예: 결합력 vs 간독성 트레이드오프, 물질특허 회피 설계, 임상 2상 실패 원인 규명)를 논리적으로 서술 |

- **부분 점수 → 금액**: `reward = score < 30 ? 0 : floor(maxReward × score / 100)`.
- **1회 수정**: 채점 결과(루브릭 · 피드백)를 확인한 뒤 1회 수정 제출 가능. `추가 지급 = max(0, reward(score₂) − reward(score₁))`.
- **모둠 단계별 상한**: 문항 보상은 단계당 모둠 합계 **`800,000 크리스타`** 상한. 상한 도달 뒤에도 문제를 풀고 피드백·직급 점수를 얻는 **연습 모드(`practice`)**는 언제든 열려 있다.

### 2.2 통로 ② — 연구 노트 꾸준 작성 보상

단계(`1.1` ~ `4.2`)마다 오른쪽 작업 영역에 있는 **연구 노트 3칸**(`① 왜 골랐나(가설·근거)` · `② 무엇을 모르나(물성·독성 한계)` · `③ 실패하면 무엇을 바꾸나(대안·백업)`)을 모둠원들이 작성하고 **[연구 노트 평가받기]**를 누르면 연구비를 지급한다.

| 항목 | 규칙 |
| --- | --- |
| **작성 단위** | 모둠 공유(칸별 분리 저장 — 세 명이 ① · ② · ③ 칸을 동시에 써도 덮어쓰지 않음) |
| **기본 최대 보상** | 단계당 **`200,000 크리스타`** (LLM 루브릭 5~6항목 채점 · 부분 점수 지급 · 수정 1회 차액 지급) |
| **분담 작성 보너스 (`×1.2`)** | 3칸(`why` · `unknown` · `fallback`)의 작성자(`updated_by`)가 서로 다른 모둠원(2인 모둠은 2명, 3~4인 모둠은 3명)이면 **`240,000 크리스타`** 지급 |
| **진행 제한 없음** | 연구 노트를 백지로 두거나 채점을 받지 않아도 다음 단계 진행 버튼은 정상 작동한다. 단, 연구 노트를 꾸준히 적어 두면 **즉시 연구비 보상**을 받을 뿐 아니라 이후 **Series A / B 투자 심사(§2.4)의 정성 점수(30%)**에 그대로 반영된다 |

### 2.3 통로 ③ — 기초 연구비 & 단계 가동률 가속 (모든 수업 형태 호환)

교사가 **① 100분 연강으로 끝내는 수업**, **② 50분씩 2~3차시로 나누는 수업**, **③ 며칠간 켜두고 자율로 맡기는 수업** 중 어떤 방식으로 운영하더라도 똑같이 작동하도록 **'달력 날짜' 대신 '파이프라인 단계(`step_id`)'와 '활성 수업 시간 10분 틱(단계별 상한)'**을 결합한다.

```text
단계 가동_i = 학생 i 가 현재 단계(step_id)에서 50점 이상 문항 1개 이상을 풀었거나
              자신이 맡은 연구 노트 칸을 작성해 50점 이상 받았다
가동률 ρ    = 현재 단계 가동 인원 / 모둠 유효 인원(교사 면제 제외)     0 ~ 1
연속 단계 s = 전원 가동(ρ = 1)을 달성한 연속 파이프라인 단계 수         0 ~ 8
가속 배율 m = 1 + ρ + 0.1 × min(s, 5)                                 1.0 ~ 2.5
```

| 모둠 4명 기준 | 단계 가동률 `ρ` | 연속 단계 `s` | 배율 `m` | 10분 틱당 충전액 | 단계당 최대 충전액 (2틱) |
| --- | :-: | :-: | :-: | --- | --- |
| 아무도 안 함 | 0 | 0 | `×1.0` | `40,000 크리스타` | `80,000 크리스타` |
| 2명 참여 | 0.5 | 0 | `×1.5` | `60,000 크리스타` | `120,000 크리스타` |
| **4명 전원 (첫 단계)** | **1.0** | **1** | **`×2.1`** | **`84,000 크리스타`** | **`168,000 크리스타`** |
| **4명 전원 (5단계 연속)** | **1.0** | **5** | **`×2.5`** | **`100,000 크리스타`** | **`200,000 크리스타`** |

- **10분 주기 자동 충전 + 단계별 2틱 상한(Cap)**:
  - 학급 시계가 열려 있는 동안 **현실 시간 10분마다** 현재 배율(`m`)에 따른 기초 연구비가 자동 입금된다.
  - 교사가 며칠 동안 학급을 켜두는 자율 수업에서 돈이 무한 복사되지 않도록, **한 단계에서 시간 경과만으로 들어오는 기초 연구비는 최대 2틱(20분 분량)**까지만 차오른다. 다음 단계로 넘어가면 새 단계의 2틱 한도가 열린다.
- **전원 가동(`ρ = 1`) 달성 시 잔여 틱 즉시 정산 (100분 단기 수업 대응)**:
  - 100분 수업처럼 빠르게 단계를 돌파하는 학급이 20분을 기다리지 않아도 되도록, **현재 단계에서 모둠원 전원 가동(`ρ = 1`)을 달성하는 순간 그 단계의 2틱 최대 충전액(`40,000 × m × 2`)에서 이미 받은 금액을 뺀 차액을 즉시 일시불로 지급**한다.
- **식는다, 꺼지지 않는다**:
  - 어떤 단계를 넘길 때 `ρ < 1` 이었더라도 연속 기록 `s` 를 0 으로 초기화하지 않고 `s = max(0, s − 1)` 로 한 칸만 식힌다(결석·지각 한 번에 팀 전체가 무너져 친구를 원망하는 일 방지).
- **가동 보호권 & 교사 면제**:
  - 심화 문항이나 연구 노트에서 80점 이상을 받으면 모둠에 **가동 보호권 1장(최대 2장)**이 생긴다. `ρ < 1` 인 채로 단계를 넘길 때 자동으로 1장을 소모해 전원 가동(`ρ = 1`)으로 인정한다.
  - 교사가 결석·조퇴 학생에게 '면제'를 체크하면 모둠 분모 인원에서 제외한다.

### 2.4 통로 ④ — Series A / B 투자 자동 심사 (교사 승인 폐지 · 4인 발굴 후보 종합 평가)

Series A · B 투자는 교사가 일일이 승인 버튼을 누르지 않는다. 실제 바이오 벤처캐피털(VC) 심사처럼 **모둠원 4명이 각자 발굴해 비교표에 올린 신약 후보 물질들의 실제 파이프라인 데이터(정량 70점) + 연구 노트 및 투자 피치 서술(정성 LLM 30점)**을 서버가 즉시 종합 평가해 투자금을 차등 지급한다.

```text
투자 지급액 = 라운드 최대 투자금 × max(0.30, 종합 점수 / 100)
```
*(최소 30% 바닥 보장 — 점수가 낮아도 최소한의 자금은 수혈받되, 4명이 제대로 후보를 발굴하고 근거를 세운 모둠은 최대 3.3배 많은 투자금을 확보한다.)*

| 구분 | **Series A 라운드** (최대 **`15,000,000 크리스타`**) | **Series B 라운드** (최대 **`25,000,000 크리스타`**) |
| --- | --- | --- |
| **신청 시점** | `2.2 ADMET 예측 · 리드 지정` 완료 후 (모둠당 1회) | `3.1 물질특허` 등록 및 `3.2 IND 승인` 후 (모둠당 1회) |
| **정량 평가 ①: 4인 병렬 발굴 기여도 (20점)** | `1.1` 표적 추천 · `1.2` 히트 찜(`claimedBy`) · **`2.1` 도킹 비교표에 모둠 유효 인원(4명)이 각자 서로 다른 후보 분자/구조 변형체를 실험해 올렸는가** (전원 참여 시 만점, 1인 독식 시 감점) | `2.1` 리드 최적화(작용기 변형 등 원본 대비 개선 시도) · `1.1`~`3.2` 단계별 실험 및 연구 노트 작성의 모둠원 간 분담 균형도 |
| **정량 평가 ②: 후보 물질 우수성 (25점)** | 주력 리드(`lead_smiles`)의 표적 도킹 `ΔG`가 기준 리간드(`referenceKcal`) 대비 달성한 **결합력 등급(`affinityStrength`)** 및 PLIP 핵심 상호작용 확보 여부 | **물질특허 학급 내 선점(독점성)** + 주력 리드의 효능(`E`) · 안전(`S`) 기반 펀더멘털 점수 |
| **정량 평가 ③: 안전성 · 백업 · 임상 설계 (25점)** | 주력 리드의 **ADMET 위험 신호 회피**(Ro5 · hERG · 간독성 · CNS 표적 시 BBB 투과/TPSA 기준 충족) + **주력과 다른 물성의 백업 후보(`backup_smiles`) 지정 여부** | 질환·표적 특성에 부합하는 **제형(경구/정맥/경피) · 용량 · 1차 평가지표 선택 타당성** 및 IND 심사 통과 성적 |
| **정성 평가: 연구 노트 & 투자 피치 (30점, LLM)** | `1.1`~`2.2` 연구 노트 요약 + Series A 피치(200~500자): ① 왜 4명의 후보 중 이 분자를 주력 리드로 골랐는가 ② ADMET 약점은 무엇인가 ③ 백업 후보의 역할은 무엇인가 | `3.1`~`3.2` 연구 노트 요약 + Series B 피치(200~500자): ① 특허 청구 전략 ② IND 용량·제형 근거 ③ 임상 1~3상 보류(CRL) 발생 시 재도전 대응 시나리오 |
| **즉시 효과** | 원장(`pitch_round`)에 크리스타 즉시 입금 · 전광판 투자 유치 공시 · **사옥 외관 Tier 2 승격** | 원장(`pitch_round`)에 크리스타 즉시 입금 · 전광판 대형 투자 유치 공시 |

### 3.2 모둠 데이터 바인딩(`LearnContext`)

서버가 그 모둠의 **실제 파이프라인 데이터**에서 실시간으로 조합한다(`programs` · `jobs` · `patents` · `steps` · `notes`).

```ts
interface LearnContext {
  target?: { id: string; label: string; cns: boolean; evidence: { genetic: number; literature: number; drug: number; expression: number } };
  screening?: { cutoff: Record<string, number>; before: number; after: number; claimedCount: number };
  docking?: Array<{ alias: string; byName: string; deltaG: number; referenceKcal: number; plip: { hbond: number; pistack: number; hydrophobic: number } }>;
  admet?: Array<{ alias: string; byName: string; radar: Record<string, number>; signals: string[] }>;
  lead?: { alias: string; properties: MoleculeProperties; backupAlias?: string };
  patent?: { code: string; rivalsSameTarget: string[] };
  ind?: { formulation: string; doseMg: number; endpoint: string };
  trial?: { phase: 'phase1' | 'phase2' | 'phase3'; outcome: 'passed' | 'held'; reason?: string };
}
```

- 문항이 `requires: ['docking']` 처럼 필요한 데이터를 선언했을 때 아직 모둠이 도킹을 실행하기 전이라면, 기본 표적/가상 예시 데이터로 폴백하거나 도킹 직후 풀도록 안내한다(진행은 막지 않음).
- **변형 시드** = `(학생 id, 학급 id, 문항 id)` → 같은 모둠원끼리도 묻는 각도 · 숫자가 다르고, 다른 모둠은 실험 데이터 자체가 다르다.
- 바인딩 값에는 **별칭**(`후보 A` · `CRX-101`)만 쓰고 SMILES 원문이나 학생 실명을 LLM 프롬프트에 넣지 않는다.

### 4.1 두 갈래 채점

| 구분 | 규칙 채점 | LLM 루브릭 채점 |

| **실행 위치** | 서버 순수 함수(`packages/web-contract/src/learn/grade.ts`) | `crista-web` 서버(`apps/server/src/learn/grader.ts`) → **OpenRouter 직접 호출** |

### 4.2 LLM 채점 계약

```ts
// crista-web 서버 → OpenRouter. 학생 글은 <answer> 안의 '평가 대상 데이터'일 뿐 지시로 따르지 않는다.
interface GradeRequest {
  graderVersion: string;
  item: {
    id: string;
    tier: 'intermediate' | 'advanced' | 'note' | 'pitch_a' | 'pitch_b';
    prompt: string;
    rubric: Array<{ id: string; weight: number; criterion: string; lookFor: string[] }>;
    modelOutline: string[];
  };
  context: LearnContext;
  answer: { text?: string; sections?: Record<'why' | 'unknown' | 'fallback', string> };
  language: 'ko';
}

// OpenRouter → crista-web 서버 (JSON 스키마 검증, 금액 필드 없음)
interface GradeOutput {
  items: Array<{ id: string; credit: 0 | 0.5 | 1; note: string }>; // note ≤ 80자
  feedback: string;                                                // ≤ 200자 (모범 답안 원문 노출 금지)
  flags: Array<'off_topic' | 'too_short' | 'injection' | 'not_korean' | 'copied_prompt'>;
}

// 서버 크리스타 계산 규칙:
//   score = round(100 × Σ(weight × credit) / Σ(weight))   (injection · off_topic 플래그 시 0점)
//   cristaReward = score < 30 ? 0 : floor(maxCrista × score / 100)
```

### 4.3 공정성 및 남용 방지

| 항목 | 대응 |
| --- | --- |
| **투명한 결과** | 루브릭 항목별 ○(1) · △(0.5) · ×(0) 와 코멘트 · 종합 피드백 공개. 학생이 한 줄 사유로 **이의 제기** 시 교사가 점수 정정 가능(`learn_correction` 차액 자동 정산) |
| **답안 베끼기** | 같은 문항 계열의 답안을 정규화 trigram Jaccard ≥ 0.6 으로 검사해 `duplicate` 판정 시 늦게 낸 쪽 0점 처리 |
| **프롬프트 인젝션** | `<answer>` 태그 격리 + 시스템 프롬프트 방어 + 정규식 사전 필터 + `injection` 플래그 시 0점 및 교사 알림 |
| **빈 제출로 가동 도장 찍기** | 단계 가동 도장은 **50점 이상** 받은 문항 또는 유효 평가(50점 이상)를 받은 연구 노트 칸만 인정 |
| **수정 악용** | 문항 · 노트당 수정은 1회로 제한하며, 오른 점수 차액(`max(0, R₂ - R₁)`)만 추가 지급 |
| **LLM 장애 대응** | 호출 실패 시 `pending` 상태로 두고 학생 화면은 막지 않는다. 개념 문항(규칙 채점)만으로도 50점 이상이면 단계 가동 도장이 즉시 찍히므로 LLM 장애가 모둠 가속 배율을 깎지 않는다 |

| 자리 | 표시 내용 |
| --- | --- |
| **위 띠** | 연구비 표시: `연구비 10,000,000 CRISTA` + 옆에 **`⚡ ×2.1 · 단계 가동 3/4`** 칩. 누르면 **학습 · 연구비 서랍**(현재 단계 문항 · 연구 노트 현황 · 가동률 · 연속 단계 · 보호권 · Series A/B 심사 현황) |
| **단계 작업 영역** | 오른쪽 열 하단의 **연구 노트 3칸** 옆에 `[연구 노트 평가받기 (+최대 240,000 CRISTA)]` 단추, 그 아래 **'이 단계 연구 문항 (개념 · 중급 · 심화)'** 아코디언 카드. **단계 확정/다음 단계 단추는 채점 여부와 무관하게 언제나 열려 있음** |
| **Series A / B 투자 심사 모달** | 위 띠 `[투자 유치 (Series A/B)]` 클릭 → **모둠원 4명이 발굴한 후보 비교 요약표 + 정량 예상 점수 게이지(70점 만점) + 피치 서술 칸(30점 만점)** 표시 → 제출 즉시 자동 심사 후 크리스타 입금 연출 |
| **사옥 지구** | 사옥 창문 = 모둠원 수(최대 4). 현재 단계에서 가동 도장을 찍은 모둠원의 창문에 불이 켜짐. 전원 가동 시 **'전원 야근' 연출**(창 전체 밝기 + 굴뚝·안테나 깜빡임), 5단계 연속 시 옥상 깃발 |
| **전광판 01** | 학습 · 투자 소식은 **긍정 소식만**: `◆ SEUM 연구진 5단계 연속 전원 가동 — 연구비 충전 ×2.5` · `◆ DAON Series A 13,500,000 CRISTA 투자 유치 성공` |
| **2축 순위** | **시가총액 순위** · **연구 역량 지수 순위**(모둠 평균 점수 × 단계 커버율 + 4인 후보 발굴 다양성) |
| **교사 화면** | 학생별 문항/노트 참여 현황 · 단계 가동 면제 체크 · 이의 제기 목록 · 채점 로그 · 학급 경제 설정(초기 크리스타 · 보상 배율 조정 · 수동 연구비 지급) |

### 6.2 API · WebSocket (`web-contract`)

| 경로 / 이벤트 | 설명 |
| --- | --- |
| `GET /api/learn/step/:stepId` | 해당 단계의 개념·중급·심화 문항, 연구 노트 평가 상태, 현재 단계 가동률(`ρ` · `s` · `m`), 남은 틱 한도 조회 |
| `POST /api/learn/answers` | 문항 제출 — 규칙 채점은 즉시 결과 및 크리스타 지급, LLM 채점은 `pending` 응답 후 WS `learn:graded` 전송 |
| `POST /api/learn/answers/:id/revise` | 문항 1회 수정 제출 (차액만 추가 지급) |
| `POST /api/learn/notes/:stepId/evaluate` | 해당 단계 연구 노트 3칸 LLM 루브릭 채점 및 크리스타 지급 (분담 작성 시 `×1.2` 자동 적용, 수정 1회 포함) |
| `POST /api/learn/pitch/:round` | Series A / B 자동 심사 요청 (4인 발굴 후보 정량 70점 + 피치/노트 정성 30점 종합 평가 → 즉시 입금) |
| `POST /api/learn/appeals` · `POST /api/teacher/learn/override` | 학생 이의 제기 · 교사 점수 정정 |
| WS 모둠 채널 | `learn:member-active`(창문 불 켜짐 · 가동률 갱신) · `learn:graded`(채점 완료) · `learn:stipend-tick`(10분 주기 충전 또는 전원 가동 일시불 정산) · `learn:pitch-funded`(Series 투자금 입금) |
| WS 학급 채널 | `district:lights`(사옥별 켜진 창문 수) · 전광판 `board_events`(긍정 소식 · Series 투자 공시) |

## 7. 구현 순서 (기준 설계 §11 연동)

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| **W3.5 학습 연구비 · 노트 평가 v1** | 크리스타(`CRISTA`) 원장 단위 적용(초기 `10,000,000`) · 단계별 개념/중급/심화 문항 시드 · `grader.ts`(서버 직접 OpenRouter 호출 · 스키마 · 캐시 · `pending`) · 연구 노트 3칸 평가(`×1.2` 분담 보너스) · 단계별 가동률(`ρ` · `s` · `m`) + 10분 틱 충전(2틱 상한 · 전원 가동 즉시 정산) · 사옥 창문 불빛 · 교사 현황표 | ① 문항·연구 노트 채점 없이도 다음 단계 이동 가능 ② 규칙 채점 즉시 · LLM 채점 수 초 뒤 크리스타 원장 입금 ③ 연구 노트 3칸을 3명이 나누어 쓰면 `×1.2` 지급 ④ 전원 가동 달성 시 사옥 창문 전체 점등 + 해당 단계 잔여 기초 연구비 즉시 정산 |
| **W5 전광판 · Series A/B 자동 심사** | 4인 발굴 후보 정량(70점) + 피치 정성(30점) Series A/B 자동 평가기 · 사옥 Tier 2 승격 · 전광판 긍정 학습/투자 소식 · 2축 순위 · 번개 문항 | 교사 승인 없이 Series A 신청 즉시 4인 도킹·ADMET·노트 점수로 투자금이 계산되어 입금되고 LED 전광판에 공시됨 |
| **W7 학습 v2** | 복습 큐(70점 미만 변형 재출제) · 분야별 연구원 직급 배지(인턴~수석) · 실패 바운티 LLM판 · 주간 학회 | 70점 미만 문항이 다음 단계에서 복습 큐로 등장 · 직급 배지가 비교표 `byName` 옆에 표시됨 |
