## 언어 수정
1. 모든 32장의 title 최대26자, subtitle 최대48자, item.label 최대15자, item.body 최대42자, item.value 최대13자, takeaway 최대58자로 반드시 줄여라. 예외는 16번 질환목록 body 최대70자. 길이가 넘으면 정보 일부를 발표자 노트로 옮겨라. 읽기 쉬운 어절과 문장을 유지하라. 본문에서 '현재 구현됨' 반복을 빼고 실제 학생 활동을 설명하라.
2. 4번/15번 상태, 17~18 스크리닝, 21~26 특허/전임상/IND/임상/허가, 30~32 수업/실습 범위와 발표자노트를 최신상태로 고쳐라. 실습은 먼저 1.1~2.2 핵심과정, 심화체험은 3.1~4.2 사전연동 확인후라는 현실적 차시 운영을 제시하라. 초기 단계만 구현됐다는 표현은 지워라.
3. 28번 교사 소개에 API/UI 같은 개발자 표현 대신 '화면 연결 중'처럼 교사가 이해하는 표현을 쓰고, 제목에서도 API를 제거하라. 31번 실습점검에서도 real/fixture 대신 '실제 계산/예시 데이터'로 쓰라.
4. 16번 원고에 없던 PDB ID는 추정하지 말고 모두 제외하라. 원문에 있던 12개 질환명/유전자명만 유지한다.
5. 22번 제목은 특정 법 조항을 단정하지 말고 동물실험 3R 윤리로, 23번 MRSD는 교육용 수리 모델에 한정하고 실제 용량 지침처럼 쓰지 마라. 일반 법률·의료 조언을 하지 않는다.
6. helpBody UI 문구를 새로 작성하라: 방향키/Space 이전다음, T목차, N노트, F전체화면, P인쇄, Home/End, 터치스와이프의 기능을 짧게 설명한다.

## 출력
코드펜스 없이 JSON 하나 {"ui":{"helpBody":"..."},"patches":[...]}.
patches 정확히32개. 각각 {"id":1,"title":"...","subtitle":"...","status":"현재 화면|개발 중|개념 안내|설계 방향","items":[{"label":"...","body":"...","value":"..."}],"takeaway":"..."}.
기존 id,layout,art,part,eyebrow는 구조 변경하지 않는다. 단 eyebrow에 이제 틀린 '개발 중'이 붙은 경우 eyebrow도 교정한 값을 포함하라.
notes는 상태나 사실이 바뀐 슬라이드에서만 새 notes(최대220자)를 포함하고, 바뀌지 않은 슬라이드에서는 생략한다. 새 노트에서 위 원칙대로 이전 노트의 틀린 내용도 제거하라.
도구 호출과 파일 작업 없이 이 대화의 이전 JSON을 바탕으로 즉시 편집하라. 새 파일이나 추가 설명은 만들지 마라.
